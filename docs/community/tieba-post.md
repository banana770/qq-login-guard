## 2. 正文（可直接复制，链接按防吞处理）

```
先说结论：不是防封，是"被踢之后自动把登录恢复回来"。

【问题】
用 NapCat 接真人 QQ 号的应该都遇到过：号被风控踢下线，机器人直接哑了。
风控期可能一两个小时掉一次，半夜根本没法管；而且被踢之后 NapCat 自己不会出码/不会重登，只能人工扫码。

【思路】
NapCat 掉线后其实会生成一个登录二维码。
我让一个安卓模拟器（MuMu）里登录同一个 QQ 号的手机 QQ 去扫这个码：
程序检测到掉线 → 重启 NapCat 出码 → 把二维码推进模拟器相册 → 用 UI 自动化打开手机 QQ 走
「扫一扫 → 相册 → 确定 → 授权」→ 最后再验证真的在线。
扫码完成后二维码立刻销毁。

【需要准备什么】
1) NapCat 已经登录你的号（开了 OneBot v11 WS）
2) 安卓模拟器 + 模拟器里装手机 QQ，登录同一个号（推荐 MuMu 12）
3) 电脑能连模拟器的 ADB（MuMu 默认 127.0.0.1:16384）
注意：模拟器里的手机 QQ 必须保持登录，它就是"扫码的那台设备"。

【怎么用】
解压后双击 0-打开配置页.bat，浏览器会打开配置页：
- NapCat.Shell 目录、OneBot WS、QQ 号、token
- adb 路径（留空会自动找 MuMu 安装目录）、设备端口、相册路径、分辨率
- "冷启动快捷方式"：如果不知道模拟器里 QQ 的位置，就在模拟器桌面长按 QQ → 创建桌面快捷方式，
  把那个 .lnk 的路径填进去即可
每项都能点"检测"，全绿后保存。
然后命令行：
  node src\cli.mjs doctor     （环境自检）
  node src\cli.mjs rehearse   （扫码链路空跑，不点击）
  node src\cli.mjs run --mode attach   （先 dry-run 观察）
  node src\cli.mjs run --mode attach --live  （自动模式）
想开机自启就双击 4-安装开机自启.bat。

【实测】
11 月 3 日自测：检测到登录态损坏 → 隐藏窗口重启 NapCat → 11 秒出新码 →
推码/扫码/授权 → 约 46 秒恢复在线，全程没人工操作；之后 AI 桥接自动重连。
（这次是人为制造掉线验证链路；自然风控掉线建议自己观察几天日志。）

【重要限制，别踩坑】
- 目前只适配 NapCat（OneBot 11），其它协议端没做
- 只在 MuMu 12 + 手机 QQ 9.2.20 实测过，其它模拟器/版本可能要调
- Linux 服务器没有安卓环境的话只能"检测+通知"，自动扫码用不了
- 不保证降低风控、不保证自愈成功率；账号被限制登录/要短信申诉时它只会停下通知你
- 仅限本人账号、本人设备，禁止代扫/批量加好友/群发营销

【开源地址】
GitHub：banana770/qq-login-guard
（打不开就 GitHub 搜 qq-login-guard，或者看楼中楼）
MIT 协议，Release 里有下载和说明；欢迎 PR 适配其它协议端。

用之前先看 README 的"安全与合规"，介意风控风险的别用主号。
```

## 5. 回帖预答（FAQ）

| 问 | 答 |
|---|---|
| 会不会封号？ | 不保证。协议端本身有风险；工具只做本人账号的登录恢复，不碰验证码/申诉。别用主号。 |
| 要装 AstrBot 吗？ | 不用，跟 AI 框架解耦，AstrBot/NoneBot/自研桥都能用。 |
| 必须 MuMu 吗？ | 目前只在 MuMu 12 实测；雷电/夜神理论上行但没验证，欢迎反馈。 |
| Linux 服务器能用吗？ | 没有安卓设备就只能"检测+通知"，不能自动扫码。 |
| 模拟器要一直开着吗？ | 要，它是扫码端；也可以配"冷启动快捷方式"，掉线时自动拉起（会占用内存）。 |
| 收费吗？ | 开源免费（MIT）。 |
| 会收集数据吗？ | 不。全部本地运行，日志在本地 `.qq-login-guard/audit.jsonl`。 |
| 二维码安全吗？ | 只在本机流转，扫完立即销毁；不要截图发群。 |
